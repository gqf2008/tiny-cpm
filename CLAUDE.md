# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`tiny-cpm` is a single-binary Rust CLI for **on-device inference on Apple Metal** (macOS / Apple Silicon only), built on the **official `candle` 0.11** crate. One binary, six models, six subcommands:

- `chat` — MiniCPM5-1B reasoning LLM, bf16 safetensors dir quantized in memory (default Q8_0, ~57 tok/s on Metal) via a vendored `quantized_minicpm5` module (GGUF not supported).
- `asr funasr` / `asr qwen3` — Fun-ASR-Nano-2512 and Qwen3-ASR speech recognition. Qwen3-ASR decode opts into the qwen3-tts fused SDPA path (`sdpa_fast_guard` in `decode_audio_datas`) — greedy ASR tolerates the non-bit-identical `simd_sum`/`fast::exp` kernel; decode ≈ `16ms + 0.045ms×KV`/token (2.1× on long audio vs the eager `repeat_kv` path). `ASR_PROF=1` prints a prefill/decode per-token breakdown.
- `tts voxcpm` / `tts moss` — VoxCPM2 and MOSS-TTS-Nano (+ MOSS-Audio-Tokenizer-Nano codec) speech synthesis, with `--ref` voice cloning.
- `tts cosyvoice3` — Fun-CosyVoice3-0.5B (Qwen2-0.5B LM + DiT-CFM + HiFT, 24kHz; ported from CrispASR C++/ggml). 8 baked voices (`--voice`), zero-shot cloning (`--ref` + `--ref-text`, required). Prefers `cosyvoice3-llm-q4_k.gguf` (QMatMul) / `cosyvoice3-flow-q8_0.gguf` (F16) over `llm.pt`/`flow.pt` when present. `--stream` = chunked streaming (first audio ~1.1 s warm (default first-chunk: hop 12, 3 steps, no CFG; upstream schedule after; env knobs CV3_FIRST_HOP/CV3_FIRST_STEPS/CV3_FIRST_CFG)).
- `tts qwen3` — Qwen3-TTS-12Hz-1.7B-Base (ported from QwenLM/Qwen3-TTS `qwen_tts`, **not** aha). Pipeline: Qwen2 BPE → talker (28-layer Qwen3 decoder, dual text+codec embedding) emits codec codebook 0 per 12.5 Hz frame → 5-layer code predictor fills codebooks 1–15 → 16 codes → custom Mimi-family speech-tokenizer decoder → 24 kHz mono. Weights: `model.safetensors` **BF16** (talker+predictor+speaker-encoder) + `speech_tokenizer/model.safetensors` **F32** (codec). Default voice, or ICL zero-shot cloning with `--ref <wav> --ref-text "<transcript>"` (ECAPA-TDNN speaker embedding prefix + codec-encoded ref codes prepended; `--ref-text` must be the *full* ref transcript or the model babbles the ref). `--language <lang>` (default `auto`). RTF ~0.40–1.9 on Metal (Q4_K GPU-sampling hits **~0.40–0.42** on an idle machine — well under realtime; BF16 ~1.04–1.9). `--stream` = chunked streaming output (first audio ~1.6–2.5 s instead of a full-utterance wait): the talker emits per-frame codes via a `generate_stream` callback, each chunk is codec-decoded as a sliding window `[emitted-25 .. now]` with the 25-frame left context trimmed, and the new PCM tail fires `on_audio`. **Fidelity trade-off**: a small chunk's 25-frame context doesn't cover the codec's receptive field, so it approximates the batch PCM near seams (measured max\|Δ\|: first=12/chunk=25 → ~1.2, chunk=50 → ~0.7, chunk=300 → 0.0 = bit-identical; guard `tests/stream_decode_equiv.rs`). Tune with `--stream-first` / `--stream-chunk` (env `QWEN3_TTS_STREAM_FIRST`/`_CHUNK`), self-check with `QWEN3_TTS_STREAM_CHECK=1`.
- `dialogue` — one-process pipeline: Fun-ASR transcribes input WAV → MiniCPM5 replies → MOSS speaks it; per-stage latency on stderr.
- `vad` — FireRedVAD-Stream-VAD speech-segment detection (safetensors + cmvn.json; `.pth.tar` rejected). stdout: one `start end` (seconds) per segment.
- `live` — realtime voice dialogue: mic (cpal) → FireRedVAD endpointing → Qwen3-ASR → MiniCPM5 (sentence-streamed) → TTS per sentence → speaker. The TTS engine is selectable: **`--tts moss|qwen3` (default `qwen3`)**. `qwen3` = Qwen3-TTS (mono 24 kHz, sub-realtime on Q4_K — the live default `--talker-quant q4_k`, unlike the tts-CLI default bf16); its codec is bundled in `<model-dir>/speech_tokenizer`, so it takes **5 positionals** (no `<codec-dir>`). `moss` = MOSS-TTS (stereo 48 kHz) and **needs `<codec-dir>`** (6 positionals). Voice cloning: `--ref <wav>`; **Qwen3 additionally requires `--ref-text "<full ref transcript>"`** (MOSS ignores it). `--input/--output` = mic-less simulation mode (output wav is mono 24 kHz for qwen3, stereo 48 kHz for moss). Without `--ref`, MOSS runs continuation mode (default voice drifts slow/odd at temp 1.7). Default = half-duplex (mic ducked during playback, no echo-loop, use headphones). `--barge-in` = mic stays live during playback; speech onset cancels the in-flight reply (LLM decode loop + TTS stream) and clears the speaker queue — **headphones required** (no AEC; speaker echo false-triggers). Works for both engines: MOSS aborts via `on_chunk -> false`, Qwen3 via a `should_abort` predicate polled per frame (see `synthesize_pcm_streaming_with_abort`). Tune onset with `LIVE_BARGE_RMS` (default 0.02) / `LIVE_BARGE_ONSET_FRAMES` (default 3). Audio IO in `src/utils/live_audio.rs`. The engine abstraction is a `LiveTts` enum (+ `LiveRef`) in `src/exec/live.rs`. **Qwen3 decode path in live**: `synthesize_pcm_batched_with_abort` (streaming generate + one batch `chunked_decode`), not the streaming sliding-window decode — see "streaming decode corrupts in a multi-model Metal process" below.

The four speech models are **ported from [`aha`](https://github.com/jhqxxx/aha)** (candle 0.9.2 → 0.11; server/rocket/tokio/modelscope/minijinja coupling stripped). Ported files carry `//! Ported from aha …` headers and keep aha's names/signatures for mechanical re-porting.

**`tiny-cpm-web`** (separate crate, `web/`) — an axum WebSocket voice server + browser client (`web/static/index.html`) aligned with the OpenAI Realtime API (2025-08 event names). Full streaming pipeline: VAD slices → Qwen3-ASR streams `input_audio_transcription.delta` per token → MiniCPM5 streams `response.output_audio_transcript.delta` (no_think + `FAST_PERSONA` by default; `TINY_CPM_CHAT_THINK=1` for verbose) → Qwen3-TTS streams `response.output_audio.delta` per codec window. The codec decoder runs on a dedicated Metal device (see the babble note below) so streaming decode is clean. Per-turn event order matches the 2025-08 Realtime API: `speech_started/stopped (item_id + audio_*_ms) → input_audio_buffer.committed → conversation.item.added(user) → response.created → transcription.delta*/.completed → response.output_item.added → content_part.added → output_audio.delta* + output_audio_transcript.delta* → output_audio.done/output_audio_transcript.done → content_part.done → output_item.done → conversation.item.added(assistant) → response.done`. Cancel/barge-in still emits the three `*.done` closers (item `incomplete`, response `cancelled`). `input_audio_buffer.clear` → `cleared`; `conversation.item.create`/`delete` → `added`/`deleted`. All events carry a globally-unique `event_id` (per-connection `IdGen`) + `item_id`/`output_index`/`content_index`. Tunables: `QWEN3_TTS_STREAM_FIRST/_CHUNK/_CTX` (first=8), `QWEN3_TTS_MAX_FRAMES` (cap; the Base talker rarely emits codec_eos for Chinese so this is the hard stop), `QWEN3_TTS_CODEC_DEVICE` (dedicated|cpu|shared). Measure with `cargo run --release --example audio_probe -p tiny-cpm-web -- <16k-mono.wav> <ws> [out.wav]`.

**History** — earlier iterations recoverable via git stash: `stash@{0}` hand-written educational engine (`TinyTensor`, ratatui TUI); `stash@{1}` candle-vllm client (bf16, ~24 tok/s); then official candle + Q8 MiniCPM5 chat; the speech models came in on branch `port-asr-tts-models`.

## Commands

```bash
cargo run --release -- chat <bf16-dir> <tokenizer.json> "<prompt>" [max_tokens] [--quant <name>]
cargo run --release -- asr funasr <model-dir> <audio-file> [max_tokens]
cargo run --release -- asr qwen3  <model-dir> <audio-file> [max_tokens]
cargo run --release -- tts voxcpm <model-dir> "<text>" <out.wav> [--ref ref.wav] [--max-len N]
cargo run --release -- tts moss   <model-dir> "<text>" <out.wav> [--codec dir] [--ref ref.wav] [--max-len N]
cargo run --release -- tts qwen3  <model-dir> "<text>" <out.wav> [--ref ref.wav --ref-text "<text>"] [--language <lang>] [--max-frames N] [--talker-quant q4_k|q8_0|none] [--stream]
cargo run --release -- dialogue <funasr-dir> <bf16-dir> <tokenizer.json> <moss-dir> <codec-dir> <input.wav> <output.wav> [max_tokens]

cargo build --release
cargo check
cargo fmt
cargo clippy
cargo test    # CPU-only unit tests (masks, feature-length math, config parsing, chat repeat-guard);
                # layer_wiring/gpu_sampling need Metal + weights in ./models/
```

Output contract: payload (chat/transcript) → **stdout**; diagnostics → **stderr**; TTS writes WAV to the given path.

Model weights are not in the repo — download into `./models/` (gitignored). MOSS models live on ModelScope (`openmoss/…`), the rest on HuggingFace.

## Architecture

- **`src/main.rs`** — subcommand dispatch only.
- **`src/exec/`** — thin per-model CLI drivers (`chat.rs`, `fun_asr_nano.rs`, `qwen3_asr.rs`, `voxcpm.rs`, `moss_tts.rs`, `qwen3_tts.rs`, `dialogue.rs`, `live.rs`): parse args → load weights → infer → emit. Model math lives in `src/models/`. Reusable engines also live here: `FunAsrEngine`, `Qwen3AsrEngine` (`transcribe_samples` for in-memory audio), `MossEngine` (`synthesize_pcm` for in-memory playback), `Qwen3TtsEngine` (`synthesize_pcm`, `encode_ref` for a reusable `RefVoice`).
- **`src/quantized_minicpm5.rs`** + **`src/token_output_stream.rs`** — MiniCPM5 chat path, vendored from candle (`quantized_llama` + streaming tokenizer wrapper). Minimal diff from upstream.
- **`src/models/`** — aha ports: `fun_asr_nano/`, `qwen3_asr/`, `voxcpm/`, `moss_tts_nano/`, `moss_audio_tokenizer_nano/`; **`qwen3_tts/`** (ported from QwenLM/Qwen3-TTS, not aha): `config.rs` (serde configs), `talker.rs` (LM + code predictor, reuses `qwen3::Qwen3DecoderLayer`), `codec.rs` (Mimi encoder + custom decoder), `speaker_encoder.rs` (ECAPA-TDNN); shared backbones `qwen3/`, `gpt2/`, `feature_extractor/`.
- **`src/common/`** (`modules.rs`, `sample.rs`, `InferenceModel`/`MultiModalData`), **`src/utils/`** (`audio_utils.rs`, `tensor_utils.rs`), **`src/position_embed/`**, **`src/tokenizer/`** — shared infra ported from aha with identical names.

## Non-obvious things that bite

- **`from_safetensors_dir`** (chat): bf16 safetensors quantized in memory at load (default Q8_0; `--quant <name>` or `TINY_CPM_QUANT` to override: q8_0/q4_0/q4_1/q5_0/q5_1/q4_k/q5_k/q6_k/q3_k/q2_k/f16/f32). GGUF files are not supported. **`quantize_onto` needs a CPU source** — mmap on CPU, then quantize onto Metal.
- **Why vendored `quantized_minicpm5`**: upstream `quantized_llama` hardcodes `head_dim = hidden/heads` (96 for MiniCPM5); MiniCPM5 has `head_dim=128`, `16*128=2048 ≠ 1536`. Patches: read `head_dim` from `config.json`; reshape attention output to `n_head*head_dim` before o_proj; always use NEOX (non-interleaved / half-split) RoPE, matching the HF `LlamaForCausalLM` reference (`rotate_half`). GGUF files are not supported.
- **Greedy (`ArgMax`) loops forever** on MiniCPM5 — `chat` uses `TopP { p: 0.9, temperature: 0.7 }`, seed `299792458`, EOS `[1, 130073]`.
- **Weight formats differ per model**: Fun-ASR = `.pt` pickles + bundled `Qwen3-0.6B/` subdir; Qwen3-ASR = mmaped safetensors (bf16); VoxCPM2 = safetensors LM + `.pth` AudioVAE (F32); MOSS = `.bin` pickles (loaded at **F32** — F16 visibly degraded quality vs the official F32 Python reference) + safetensors codec + sentencepiece `tokenizer.model`.
- **MOSS**: `--codec` defaults to `<model-dir>/../MOSS-Audio-Tokenizer-Nano`; `--max-len` default 100 frames (~8 s at 12.5 fps — the codec's true rate); output WAV is stereo.
- **Metal-risky ops**: `conv_transpose1d` (VoxCPM AudioVAE), per-frame `arg_sort`/`to_scalar` syncs (MOSS, perf only). Compile-clean; watch at first real run.
- **ASR prompt templates are rendered manually** (no minijinja): Qwen3-ASR expands `<|audio_pad|>` placeholders; Fun-ASR splices adaptor outputs at `fbank_mask` positions.
- **ASR decode is GPU-forward-bound, not sampling-bound** — Qwen3-ASR's `generation_config.json` ships `do_sample: false, temperature: 1e-6`; `Qwen3AsrEngine` honors `do_sample` (`src/exec/qwen3_asr.rs`) so greedy uses `ArgMax` (4-byte readback) rather than candle `Sampling::All{1e-6}` (full 151936-vocab divide+softmax + ~607KB GPU→CPU readback + O(V) multinomial per token). Measured: removing the multinomial did NOT change per-token wall time — `sample` timing is the GPU-foward sync wait, so the real levers are attention (fused SDPA) + quantization, not sampling. Fun-ASR decode now also routes through `sdpa_fast_guard()` (`src/exec/fun_asr_nano.rs::transcribe`), same fused path Qwen3-ASR uses; it samples (top_k/top_p), so the fused kernel's `simd_sum`/`fast::exp` drift is harmless.
- **macOS requires the Metal Toolchain** (one-time): `xcodebuild -downloadComponent MetalToolchain`.
- **Qwen3-TTS weight nesting**: conv weights in this checkpoint sit under `.conv.weight`/`.conv.bias` (so `CausalConv::new` does `vb.pp("conv")`); the RVQ `input_proj`/`output_proj` use a bare `weight`. Check tensor names against `config.json`/safetensors headers, not the upstream Python attribute path.
- **`gen` is a Rust 2024 reserved keyword** — can't be a variable/field name (the talker/generation code uses `gen_cfg`). Applies project-wide.
- **Qwen3-TTS speaker encoder stays F32** even though the talker runs BF16: its STFT/mel front-end is F32, and the ECAPA convs would hit an F32→BF16 dtype mismatch otherwise. Cast its output embedding to `talker_dtype` before the ICL prefix.
- **Qwen3-TTS talker quantization is opt-in and BF16 is the default** — `--talker-quant q4_k|q8_0|none` (env `TINY_CPM_QWEN3_TTS_TALKER`), default `none`. It buys **memory (~3 GB→~1 GB)** and is roughly speed-neutral-to-faster on this 1.7B (post-prealloc-KV, idle machine: Q4_K **~0.40–0.42** is the fastest config and is well under realtime; BF16 ~1.9; Q4_K's bandwidth win beats its dequant overhead here). `src/models/qwen3_tts/quantized_talker.rs` mirrors the Qwen3 layer (per-head QK RMSNorm, no bias) with 7 QMatMuls/layer, F32 activations, runtime in-memory `QTensor::quantize_onto` (no GGUF — needs a **CPU**-mmaped VarBuilder source). The talker backbone is a `TalkerBackbone` enum (Full/Quant) extracted from `forward_step`.
- **Quantized backbone must NOT apply the final norm** — the `Full` path (`Vec<Qwen3DecoderLayer>`) returns *raw* layer outputs and `Talker::forward_step` applies `self.norm` (then `codec_head`) once. `QuantizedTalkerBackbone::forward` must do the same: returning a *normed* output makes `forward_step` norm it a **second** time (double RMSNorm re-scales the already-normalized hidden), which is exactly what made every quantized/passthrough run babble from frame 1 while the prompt (frame 0) looked fine. Regression guard: `tests/layer_wiring.rs` (one reference `Qwen3DecoderLayer` vs the F32-passthrough mirror must be **bit-exact** in both prefill and single-token decode).
- **Qwen3-TTS Metal benchmark (M4)**: tiny-cpm is the **fastest of three implementations on Metal** — post-GPU-sampling Q4_K RTF **~0.40–0.42 (sub-realtime, idle machine)** vs qwen3-tts-rs 4.11 (its opts are CUDA-only) vs audio.cpp 7.93 (bottleneck = ggml codec decoder, 82% of wall; audio.cpp's real track is CUDA at RTF 0.13–0.19). (Pre-GPU-sampling Q4_K was 1.28.) Full three-way tables + repro in **`docs/qwen3_tts_metal_bench.md`**. Gotcha: audio.cpp's Base model **truncates at ~0.4 s without `--reference-text`**, which made early runs look spuriously "fast" — always pass the full ref transcript.
- **Qwen3-TTS sampling runs entirely on the GPU** (codebook 0 **and** the code predictor's books 1–15; `QWEN3_TTS_CPU_SAMPLE=1` reverts the predictor to per-step CPU sampling). Both code0 and the 15 predictor steps need the sampled token to build the next input, which naively forced a blocking `to_vec` GPU→CPU readback per step (1 for code0 + 15 for the predictor per frame). `gpu_sample_token` does temperature + Gumbel-max argmax as on-device tensor ops; code0 additionally applies a precomputed GPU suppression bias (`[2048,3072)` except `codec_eos`) and a GPU repetition-penalty multiplier (a `(1,vocab)` tensor `scatter`ed with the penalty each frame, idempotent per distinct token = HF semantics). The talker's `forward_step_gpu` keeps its logits on the device, so **the only readbacks per frame are 16 scalars** (1 code0 u32 + 15 predictor u32) instead of a full 3072-float logits vector + 15 vectors. top-k/top-p are skipped (defaults top_k=50/top_p=1.0 only trim the negligible tail). **Result: Q4_K on an idle machine is sub-realtime (RTF ~0.40–0.42).** The residual per-frame cost is the 15 sequential 5-layer predictor forwards — pure GPU weight-bandwidth, NO syncs to save (`gpu_sample_token` is all device ops). Micro-benchmarks show a candle/Metal matmul launch costs only ~39µs, and a pipelined Q4_K m=1 GEMV reaches **63–86 GB/s** (~70% of the M4's DRAM peak; the mv kernel is already m=1-optimal — its mm variant measures **4–8× slower** at m=1). So this is **m=1 single-token occupancy-bound (40–130 GFLOP/s vs ~2400 peak), NOT launch-bound** — also why 0.6B ≈ 1.7B in RTF. **Every remaining lever is measured-closed** (2026-08): norm+rope+KV fusion slower (0.48 vs 0.42), per-frame cos/sin table neutral, q2_k babbles / q3_k slower, custom m=1 GEMV no headroom (mm 4–8× worse), speculative decode debunked (predictor top-1 confidence only 5–9% — the RVQ residual books are near-random). (ICB / `MTLIndirectCommandBuffer` kernel-graph capture was evaluated and rejected: it saves launch overhead, which isn't the bottleneck, and `setKernelBuffer` hard-binds buffer addresses at record time — a poor fit for AR + KV-cache's per-frame-reallocating pool; even ggml-metal doesn't use ICB.) **RTF ~0.40–0.42 is the genuine eager-candle ceiling** — below that needs a lazy-graph runtime (mlx-style whole-frame compilation). Correctness guards: `tests/gpu_sampling.rs` (greedy==CPU argmax; Gumbel-max is a valid categorical draw) for TTS codebook sampling; ASR guards live in `tests/asr_correctness.rs` (Qwen3-ASR greedy transcript == committed golden) and `tests/layer_wiring.rs` `mirror_asr_layer_matches_reference_decode` (ASR decoder layer vs `QuantizedTalkerLayer` mirror, prefill+decode). Profile per-stage with `QWEN3_TTS_PROF=1` (note: the per-frame `sample0` now *absorbs* the talker's GPU forward time, because its `to_vec1` is the frame's first sync — compare **total** wall-clock, not per-stage splits). **Benchmark caveat**: RTF is only meaningful on an idle machine — one competing GPU/CPU process swings identical runs 2–6×; check `sysctl -n vm.loadavg` (~<3) first.
- **Qwen3-TTS preallocated KV append** (the 0.94 → 0.40 RTF jump, commit `3d32263`): the code-predictor decode path (and the quant talker) used to `Tensor::cat` k/v into a growing cache — 2 kernels/layer. The fused-RoPE Metal kernel (`rope_fused.metal`) now appends k/v **directly into caller-owned preallocated `(kv_heads, kv_cap, head_dim)` buffers** (per-layer; cap = 17 for the predictor, 4096 for the talker) and returns rank-4 strided views (`unsqueeze(0)`), which the fused SDPA reads via its explicit `k_stride`/`v_stride` (per-head stride = `kv_cap*head_dim`, positions contiguous) — zero copies. The kernel consumes the post-transpose(1,2) views directly via layout stride params (decode: seq-stride = heads*dim, head-stride = dim; prefill: contiguous) — do NOT hardcode the transpose strides, the prefill inputs are contiguous. Per-layer decode kernels dropped ~15 → ~13 and the predictor went 23.8 → 16.1 ms/frame (PROF_SYNC), fwd 13.8 → 10.2 ms/frame. **Gotcha**: `Tensor::cat`'s output is a *strided view* of the source buffer (seq-stride 1024, NOT contiguous) — the Full/BF16 path still cats, so `sdpa_vector_attention` must copy k/v unless the seq-dim stride == head_dim; the quant path's preallocated views skip the copy (`k_layout.stride()[2] == head_dim`). Bit-exactness guard: `tests/layer_wiring.rs` (mirror vs reference in prefill AND decode, both talker and predictor).
- **Qwen3-TTS streaming decode corrupts in a multi-model Metal process** — in `live` (Qwen3-ASR + MiniCPM5 + Qwen3-TTS sharing one `Device::new_metal(0)`), the codec decoder's streaming sliding-window `decode` — small per-chunk windows interleaved with the talker's GPU forwards — produces babble, wrong-from-frame-1, while a single batch `chunked_decode` of the **bit-identical** codes is clean. Root cause: candle 0.11's Metal buffer pool aliases the small streaming-decode buffers with the talker's GPU workspace once ASR+LLM have churned the pool. NOT sampling, NOT quantization, NOT concurrency, NOT load-order — all disproven (full-greedy code sequences are bit-identical standalone vs live, yet streamed audio still babbles). Two fixes: (a) `live` uses `synthesize_pcm_batched_with_abort` (streaming GENERATION preserves barge-in abort via the per-frame `should_abort` predicate + one batch `chunked_decode` at the end); (b) `tiny-cpm-web` runs the codec **decoder on a separate `Device::new_metal(0)`** (its own buffer pool/queue) so the streaming sliding-window decode is isolated from the talker's workspace — clean incremental audio. The standalone `tts qwen3 --stream` CLI runs a single model, so its streaming sliding-window decode stays clean there. See [[the `CodecDevice` enum]]: `CodecDevice { Shared, Dedicated, Cpu }` (env `QWEN3_TTS_CODEC_DEVICE`) in `src/exec/qwen3_tts.rs`; `load_with_quant_and_codec_device` builds the `CodecEncoder` on the main device (ref codes stay on the talker device for ICL) + `CodecDecoder` on the codec device, assembling `SpeechTokenizer` directly from its pub fields (`codec.rs` untouched). All decode call sites move codes to the codec device first (`to_device` is a no-op when Shared). Verified: streamed audio is speech-like across runs (peak ~30k/32767, rms ~3.5-4.4k, RMS dynamic range 0.005→0.25 with pauses — not constant-noise babble); standalone `QWEN3_TTS_STREAM_CHECK=1` max|Δ| = 1.04 (dedicated) vs 0.73 (shared), both window-approx-sized, len Δ=0.
- **Qwen3-TTS with no `--ref` gives every sentence a random speaker** — the talker injects `spk_embed` only when `ref_voice` is `Some` (talker.rs ~L775); otherwise the prompt is unconditional, so the speaker identity comes entirely from the sampling draw, and candle's Metal RNG advances its on-GPU atomic seed on every `rand_uniform` call (`atomic_store_seed` in `random.metal`). `web`/`live` synthesize each LLM sentence with a separate `synthesize_pcm_*` call → **each sentence of one reply is a different random speaker** ("一段文本三种声音"). Two same-text runs look bit-identical only because each fresh process starts from `set_seed(299792458)`; within one long-lived process the draws diverge. **Fix: always pass a fixed `--ref <wav> --ref-text "<transcript>"`** so every sentence reuses one speaker embedding (verified: 3 sentences → speaker-embedding cosine 0.93–0.97; probe `web/examples/speaker_probe.rs`). The repo's `ref-clone.wav` (22 s) + its Qwen3-ASR transcript works.
- **MiniCPM5 `no_think` + multi-turn history makes the 1B model repeat the previous assistant turn verbatim** — `chat::generate_reply_*` `no_think=true` appends an empty pre-closed `<think>\n\n</think>\n\n`; with history in the prompt the model then copies the last assistant text (8 tokens, e.g. "你好！有什么我可以帮助你的吗？") instead of answering. Single-turn/no-history `no_think` is fine (live.rs uses it; unaffected). **`web` must use think mode (`no_think=false`)**: the model reasons inside `<think>…</think>` and `stream_clean` only forwards post-think text, so reasoning is never shown/spoken. Fixed in `2419a0f` (web/src/main.rs).

## Code conventions

- Vendored/ported files stay minimal diffs (candle upstream / aha); don't restyle them, keep original comments (including Chinese ones).
- `src/main.rs` and `src/exec/*` stay thin drivers.
- Errors: `anyhow::Result` in drivers; ported aha code keeps `anyhow::Result` (verbatim-port wins); `candle_core::Result` only in the vendored candle files.
- Keep `AGENTS.md` and this file in sync.
